## 1. 证据阶梯

证据等级按 Spec 固定：

1. `规划`
2. `静态确认`
3. `Mock 通过`
4. `真实只读通过`
5. `本地页面通过`
6. `已部署通过`

原则：低一级证据不能支持高一级结论；没有运行命令、测试数量、真实样本和产物路径时，任务保持未完成。

## 4. 覆盖报告格式

每批生成本地 `coverage-report.json`，至少含：

| 字段 | 约定 |
| --- | --- |
| `report_id` | 报告稳定 ID |
| `batch_id` | B01 至 B18 |
| `dataset_version` | 对应时间线源文件版本 |
| `generated_at` | 生成时间 |
| `source_adapters[]` | 实际使用的来源和版本 |
| `units[]` | 每个 region×period×target_scale 单元 |
| `queries[]` | 查询词、来源、时间、总数、候选数、接受数、失败原因 |
| `state` | `checked_nonempty`、`checked_empty`、`unbuilt`、`failed` |
| `event_count` | 接受事件和 placement 数 |
| `evidence_count` | 日期和主张级来源数 |
| `empty_reason` | 已查为空时的口径和证据范围 |
| `failure_reason` | 403/429/超时/TLS/人机验证/接口拦截等 |
| `unresolved[]` | 未决问题和归属任务 |

覆盖报告不把“未构建”写成空数据，也不把“已查为空”写成空白。

## 5. 续跑和失败重试

- 每批保存 `cursor`、已完成查询、已处理 source ID 和失败列表；重启从 cursor 继续。
- 幂等键：来源 ID + 本地 event/period 范围；重复运行不得重复 placement 或 article。
- 超时和 429：指数退避后重试；设置上限和批次检查点。
- 403、TLS 失败、CAPTCHA、条款不明：不自动重试，标 failed 并记录原因。
- schema、孤儿、边界或证据校验失败：本批不合并，保留上一个可用版本。
- 批次部分成功：允许保留已通过事件，但覆盖报告必须列出未完成单元。
- 批次过大：按地区、世纪或十年拆批，不能降低覆盖状态。
- 每批完成必须更新 Spec/Todo/索引和覆盖报告。

- P2-3 完成是规划级完成；尚无可运行项目、无自动化测试、无模型调用和本地页面。
- P3 开发仍需明确授权；未经授权不创建工程、不安装依赖、不执行全球采集。
