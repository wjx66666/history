# 全球历史分层时间线 Spec v1

日期：2026-09-30　状态：执行中；P1-P4、P6-1 已取得相应证据，P5 首批 12 条真实实体样本已导入复核，全球构建未完成　证据等级：规划 + Mock + 真实实体只读 + 本地页面（不等于真实模型或全球验收）

## 1. 背景与目标

为个人在本机电脑浏览器中快速学习全球历史。以横向时间线为主要入口，逐层缩小预制的时间段；在具体事件的独立页面阅读数分钟可读完的中文图文讲解，并可临时向 AI 追问。底层跨地区事件和人物关联支撑导航，不能以一张拥挤的关系网代替时间线。

第一版目标覆盖全球各地区、从有可靠记载的历史到当代的主要事件，包含政治、战争、科技、思想、宗教、艺术、经济、灾害等。主页给史前留概览，但史前不做逐层下钻。这里的“全球”和“全部”指产品范围，不承诺收尽历史上发生过的每件事；没有可靠资料的区间允许为空。

非目标：移动端、多人注册或公开服务、人物独立文章页、主题筛选、网页内人工编辑器、自动同步上游数据、任意年份框选、AI 即时生成时间线、神话传说当作史实、AI 绘制伪史料图片。

## 2. 已确认的用户路径

1. 主页展示全球横向主线；可切换全部 / 中国 / 外国，并按地理地区、具体国家或文明多选。地区分行组织；只筛罗马时只显示罗马相关线，不显示欧洲其余内容。
2. 同期政权可并排、时间范围可重叠；跨地区的同一事件在相关线重复出现，但共用一个稳定事件 ID 和一份讲解。筛选和当前位置在下钻、返回、讲解页往返时保持。
3. 点击预制时间段切换到该段的下一层时间线；每层只显示适合当前尺度的主要事件和预制区间。逐层到约十年为止；无法可靠细分的段不显示继续下钻入口。点击具体事件进入独立讲解页。
4. 同一分段内位置按实际年代比例计算；主页允许对史前、古代、近现代等大跨度区间使用不同尺度，但须明确显示分段和刻度，不能让跨段距离看似等比例。
5. 讲解首次打开时由 AI 实时检索、生成中文简明内容、相关事件和有来源的真实图片，保存本机；再次访问直接读取。资料不足时只写可支持的简短内容并标不确定性；无可用图片时纯文字。手动“重新生成”覆盖当前讲解，不在 UI 保留旧讲解版本。
6. 问答每次可实时检索，仅留在当前会话，不保存。搜索事件、人物、国家或文明；人物搜索返回相关事件，不生成独立人物页。讲解中的人物、地点、事件可跳转至现有事件或对应时间线位置，无目标时不制造虚假链接。
7. AI 在正式讲解或追问时若发现有确凿依据的缺漏或错误，可自动新增、修正事件，也可调整时期边界和分段，并由 AI 判断事件层级。一个可追溯的可靠来源即可，维基百科或 Wikidata 可作为来源；有冲突保留并标注争议。修改原始时间线文件，且必须有修改记录和可恢复备份。

## 3. 当前事实与数据源决策门槛

2026-09-30 已完成 P3/P4 本地 Mock、隔离副本及页面功能。P5 导入 P1-2 的 12 条 Wikidata 实体样本，并复核 EntityData 日期、精度和历法，见 [复核记录](p5-sample-audit.md)。8/18 批 partial，10/18 批 unbuilt；外部参考未逐条核验，不能视为全球覆盖或完全验证的史实。相邻 `LightRAG` 是独立项目。**稳定的规模化数据源及产品运行时 AI 提供商尚未最终选定**。

候选基线：Wikidata 的实体 ID、时间属性、类型和地区关联可提供全球跨类型骨架；维基百科和博物馆/机构页面作为事件核查与讲解来源。先对多个文明、古代/近现代、战争/非战争抽样验证事件粒度、中文标签、日期精度、覆盖、引用、获取限制和许可。特别核验“事件”而非人物/作品恰好带日期的实体、古代纪年与跨年事件。Wikidata 单独不足以保证全球逐十年高质量事件库；不足处须在覆盖报告明确标记，不得让 AI 无来源补齐。全量导入、批量下载和外部 API 调用属于后续开发/数据阶段。

## 4. 建议数据契约（实施前由样本校正）

P2-1 定稿候选见 `data-contract-p2-1.md`：已定义时间 ordinal、半开区间、稳定 ID、period/event/placement/region/relation/evidence/article/image 和写入不变量。

用户动作 → 时间线路由（段 ID、筛选、视口位置）→ 本地查询 API → 时间线主文件/讲解缓存/本地媒体 → 页面。首次讲解或追问 → 检索与模型服务 → 来源校验及实体匹配 → 讲解保存或有证据的数据修订 → 页面；失败则显式显示离线/检索失败状态，不写入猜测内容。

建议独立对象：`period`（稳定 ID、父 ID、起止时间、标题、尺度、是否可展开、排序）、`event`（稳定 ID、多语言原名/中文名、参考日期或区间、精度、争议说明、来源、创建/修订来源）、`event_placement`（事件 ID、时间段 ID、地区/文明 ID、当前层显示权重）、`region`（层级和历史适用时段）、`relation`（来源事件、目标事件/人物/地点、关系类型、证据）、`article`（事件 ID、正文、引用、图片元数据、生成时间和模型信息）。跨线放置只创建多个 placement，不复制事件。源 ID 与本地 ID 分离，合并时保留外部标识和来源。

年代内部建议使用有序的标准化日期/年份，不用简单字符串排序；公元前年份、无公元 0 年、日期范围、约数和年代争议均需测试。某层十年是目标粒度而非要求每段恰好十年。事件落点与区间边界遵循统一的半开区间或明确规则；跨段持续事件和政权以覆盖区间展示。可展开段须有已存在的子段，且子段与父段、事件放置保持一致。

原始时间线是可找到的版本化文件（建议 `data/timeline/`），本地存储可另有查询索引。索引须由源文件重建，不能成为另一个不可追溯的事实源。讲解、媒体和运行数据与原始文件分开；由代码写入时仅在验证通过后原子替换源文件，先生成备份及含旧值、新值、来源 URL、时间、触发事件的审计记录。重新生成覆盖讲解，但时间线修改仍可恢复。并发请求按事件 ID 去重，跨事件改写源文件要串行化及版本检查，避免丢失更新。自动改动边界后重算放置、索引和路由，并验证没有孤儿段或丢失事件。

## 5. AI、图片与可信度

检索结果不能直接当指令执行；模型输出必须经过结构校验、来源链接校验、日期/实体去重和层级不变量校验。一个来源是**最低写入门槛**而非真实性保证；不可核查或仅有模型自述的事实不得入库。矛盾来源应保留参考落点并显示“年代有争议”及不同说法，不能静默择一。修改其他地区/年代允许，但每个变更独立附证据。问答不保存，问答引发的修订与审计记录仍须保存。模型错误、检索超时和离线不覆盖已有讲解或数据。

只选真实图像，保存到本地并保留原页面、作者、授权或使用条件、说明和获取时间。个人本机使用也不意味着“署名即可任意下载”；先检查站点允许的获取方式与许可，不能合法下载时用链接或不配图。图片与正文缓存后可离线打开；首次生成、重新生成和追问需联网。外部 API 密钥置于本机配置/环境，不进源文件、备份、日志或页面。

## 6. 实现建议与依赖（非既定技术选型）

P2-2 首轮架构见 `architecture-storage-p2-2.md`：Node/TypeScript 单栈、JSONL 事实源、SQLite 派生索引、本地 Fastify API、React/Vite 页面和串行修订事务。

建议分离数据构建器/校验器、本地服务和桌面网页。数据可用可审阅的 JSON/JSONL 或结构化文件，查询用本地索引；前端绘制带地区泳道、比例刻度、筛选、下钻和面包屑的时间线。技术框架、数据库、检索及模型服务在数据源取样后决策。首轮先以跨时期、跨地区小样验证交互与契约，再执行一次性全球构建；不能把演示样本称作全球完成。

一次性全球逐十年预制是高规模且依赖数据质量的交付：需要定义每一时期/地区的覆盖清单、预计节点数量、数据缺口和构建耗时。允许没有可靠事件的空段，但必须区别“经检查为空”和“未构建/采集失败”。若来源不足以完成，保留未完成状态而不降低为伪造事件。

## 8. 风险、待验证与时间线

- 全球主要事件逐层到十年的质量与总量、可靠数据的全球偏差，尚未实测；是首要可行性门槛。
- P1-3 首轮也未能从当前访问条件证明全球十年层可达：14 个查询共筛出 14 个实体记录（1 个查询零结果，另一个查询包含 2 个同名义项），13 个有日期记录的实体中只有 6 个主日期带可见引用；节点量只能给设计情景，不能给全球事实总数。
- P1-4 首轮只完成 DeepSeek 官方文档级能力核查；OpenAI、Anthropic、Gemini 当前不可达，未做模型调用。DeepSeek 文档明确内建 web search、file search 等工具不被支持，引用必须由本项目自行检索和校验；产品运行时模型仍未选定。
- 史前与“从有记录开始”在各文明并非同一日期，主页须按地区表达，不强制统一起点。
- AI 自主修改时期结构风险高；必须先用模拟修改验证原子性、冲突处理、回滚和来源约束，不能只有提示词防护。
- 来源可访问性、图像授权、机器翻译中文名、同名事件消歧和古代年表冲突待抽样确认。
- 推荐阶段：需求/数据源取样 → 数据契约与全球构建方案 → 核心浏览 → AI 讲解与图片 → 自动修订与恢复 → 全球全量构建 → 只读联调/视觉/安全/本地验收。具体工期需在取样得到规模数据后估算，不虚构日期。
