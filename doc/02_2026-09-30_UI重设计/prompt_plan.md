# UI 重设计 Prompt Plan

日期：2026-09-30　状态：设计完成，实施未授权　证据等级：规划 + 静态确认

## 使用边界

本计划只把 [UI 重设计 Spec v1](ui-redesign-spec-v1.md) 转成可执行阶段。当前用户授权范围是“先设计并生成文档”，因此不得在本轮修改 `src/`、测试、依赖、数据或远端分支。后续每个阶段开始前必须确认用户授权对象。

## U0 现状审查（已完成）

- 输入：`doc/README.md`、原 Spec、架构、Todo、`src/web/App.tsx`、`src/web/styles.css`、当前 JSONL 数据和本地页面。
- 产物：本目录 Spec 中的“当前事实与证据”。
- 允许动作：只读文件、只读本地 API、截图观察。
- 禁止动作：改代码、改数据、重新导入、部署。
- 证据：16 事件、40 placements、7 地区、6 时段；1440/390 页面观察；API 静态确认。
- 停止条件：发现事实与文档冲突时先记录，不擅自改实现。

## U1 设计规格（已完成）

- 目标：确定信息架构、主视图、年表退路、对比栏、URL 状态、异常状态和验收标准。
- 产物：`ui-redesign-spec-v1.md`。
- 允许动作：在 `doc/02_2026-09-30_UI重设计/` 新增设计文档并更新文档索引。
- 禁止动作：业务代码、样式、测试、数据修改。
- 停止条件：Spec 中所有 U-01 至 U-12 均可由后续命令或页面行为判定。

## U2 实施准备（待授权）

- 输入：Spec、现有 `App.tsx`、`styles.css`、`tests/e2e/timeline.spec.ts`。
- 目标：拆出 ViewModel 和布局纯函数，列出具体组件边界及测试清单。
- 允许动作：只读设计细化；如用户授权开发，才可新增/修改前端文件。
- 预计范围：
  - `src/web/timeline-view-model.ts`
  - `src/web/timeline-layout.ts`
  - `src/web/components/` 下的展示组件
  - `src/web/App.tsx`
  - `src/web/styles.css`
- 验证：`npm run typecheck`。
- 停止条件：任何 API 或数据事实源变更都必须停下来另行说明。

## U3 前端实施（待授权）

- 目标：实现时间矩阵、紧凑时段导航、状态筛选、年表列表、焦点高亮和 2-3 项对比栏。
- 允许动作：修改前端源码与样式，新增纯函数测试和 E2E 选择器。
- 禁止动作：不新增后端接口、不改 JSONL、不重建数据、不接真实模型、不部署。
- URL 要求：`period`、`regions`、`status`、`view`、`focus`、`compare` 可恢复。
- 验证命令：
  - `npm run typecheck`
  - `npm test`
  - `npm run build`
  - `npm run test:e2e`
  - `npm run test:smoke`
- 停止条件：任一现有讲解、媒体、问答或修订测试回归。

## U4 视觉与可访问性验收（待授权）

- 目标：验证 1440×900、1024×768、390×844 下无重叠、无水平溢出、键盘可达。
- 允许动作：本地构建、本地页面、Playwright 截图和只读测量。
- 证据要求：每个视口至少一张截图；聚合标签、空态、对比栏和移动端年表均有证据。
- 停止条件：出现文本溢出、控件遮挡、焦点不可见或状态只能靠颜色辨认。

## U5 文档同步与收尾（待授权）

- 目标：回填 Todo、README 时间线、测试数量、命令、截图路径、证据等级和限制。
- 允许动作：更新文档。
- 禁止动作：删除历史限制、把本地页面写成部署通过、把设计文档写成代码完成。
- 阶段汇报必须包含：阶段、授权范围、完成内容、产物绝对路径、验证命令与结果、测试数量、最高证据等级、限制与未完成、明确未执行的高风险动作。

## U6 提交与推送（不在当前授权内）

- 只有在用户明确要求提交或推送时执行。
- 提交前检查 `git status`、`git diff --check` 和敏感内容。
- 推送失败只报告真实错误，不索要或暴露凭据。
