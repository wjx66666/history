# UI 重设计 Spec v1

日期：2026-09-30　版本：v1　状态：设计候选，未实施代码　证据等级：规划 + 静态确认 + 本地页面观察

## 1. 背景与问题

当前页面已经解决“事件标签互相重叠”的紧急问题，但解决方式退成了按地区分组的事件卡片列表。对历史研究场景来说，这带来三个新的问题：

- 时间位置被弱化：同一地区内的事件按网格排列，用户只能读先后，难以直观看出间隔、重叠和同期关系。
- 跨地区关系被弱化：同一事件在多个地区重复成普通卡片，看不出它们共用一个事件，也无法一键对照。
- 数据稀疏被放大：当前正式数据只有 16 个事件、40 个 placements、7 个地区、6 个时段；欧洲 placement 占比较高。大面积卡片会让“样本少”看起来像页面内容不足，而不是明确的覆盖状态。
- 对比能力缺失：用户只能逐个进入详情页，再把信息记在脑中，无法并排比较 2 至 3 个事件的时间、地区、类型和证据状态。
- 当前首屏信息层级偏散：覆盖提示、统计、刻度、时段卡、地区事件区都在抢占注意力，但没有一个明确的“主画布”。

本设计把主页从“地区列表页”改成“时间标尺驱动的地区矩阵”，并新增轻量事件对比栏。目标不是增加装饰，而是让稀疏样本也能清楚表达：什么时间、哪些地区、同一事件是否跨地区、哪些内容尚未核验。

## 2. 目标与非目标

### 目标

1. 首屏直接进入可用时间线，不做营销式首页或说明页。
2. 主视图保留实际年代比例：点事件用标记，区间事件用横条，时间刻度在上下各出现一次。
3. 地区以矩阵行呈现；同一地区内的事件按真实时间定位，不再退成普通网格列表。
4. 同一事件跨地区出现时，通过同一事件 ID、统一视觉标记和高亮联动建立关系。
5. 支持选择最多 3 个事件放入对比栏，并排查看时间、区间重叠、共同地区、类型和数据状态。
6. 数据覆盖状态清晰可见：已查为空、未构建、加载失败、筛选无结果必须互相区分。
7. 筛选、时段、视图模式、焦点事件和对比选择进入 URL，刷新、返回和分享后恢复。
8. 移动端默认使用更适合阅读的年表列表，同时保留可切换的简化时间轴。
9. 本阶段只交付设计文档，不修改业务代码、不新增依赖、不改变事实源数据。

### 非目标

- 不做任意年份框选或自由缩放到底层日期；原始 Spec 仍以预制时间段为准。
- 不新增公开服务、多用户、账号或在线协作功能。
- 不把事件详情页改成复杂知识图谱。
- 不在本阶段实现真实模型、真实图片或全球数据构建。
- 不用视觉密度掩盖当前 P5 数据未完成的事实。

## 3. 当前事实与证据

### 数据事实

- 正式时间线源文件当前含 7 个地区、6 个预制时段、16 个事件、40 个 placement、16 条 evidence。
- 9 个地区×时期批次为 `partial`，9 个批次为 `unbuilt`。
- 事件数据状态目前只有 `provisional` 和 `insufficient`；尚无 `verified` 事件。
- 同一事件可通过多个 placement 出现在多个地区，例如跨欧洲、地中海或西亚的事件。

### 页面事实

- 现有主页为左侧筛选 + 主内容区；主内容包含概览统计、刻度、下级时段卡和地区事件卡片。
- 现有实现已避免标签重叠，并通过 1440、1024、390 宽度 E2E 检查。
- 现有 API 提供 `/api/timeline`、`/api/periods/:id`、`/api/events/:id`、`/api/search`；尚无专门的比较接口。
- 现有事件页已包含事实摘要、媒体、讲解、来源、临时追问和修订提案入口。

### 证据边界

本轮依据本地页面截图、源代码和数据文件做静态确认；没有实施代码，也没有重新运行业务测试。设计验收必须通过后续自动化和本地页面证据确认，不能只凭文档标记完成。

## 4. 设计原则

1. 时间轴是主画布，地区行、筛选和详情都服务于时间比较。
2. 对稀疏数据诚实：空地区、未构建时段和来源不足直接显示，不用装饰性内容填满。
3. 对比不离开上下文：用户在不丢失时间线位置的情况下选择并比较事件。
4. 先保证可读，再保证密度：标签放不下时使用聚合和列表，不缩小到不可读字号。
5. 颜色只表达稳定语义；地区和事件类型不依赖大面积彩色卡片。
6. 所有交互都有键盘、触控和窄屏退路，不依赖 hover。

## 5. 信息架构与路由

### 路由

| 路由 | 用途 | 状态 |
| --- | --- | --- |
| `/` | 时间线主视图、筛选、时段切换、搜索、对比栏 | 重设计 |
| `/event/:eventId` | 单个事件详情、媒体、讲解、问答、加入对比 | 局部重设计 |
| `/event/:eventId?return=...` | 返回时间线并恢复状态 | 保留 |

### URL 状态

主页查询串建议固定为：

| 参数 | 示例 | 说明 |
| --- | --- | --- |
| `period` | `period_global_sample` | 当前预制时段，沿用现有语义 |
| `regions` | `reg_europe,reg_west_asia` | 地区多选，沿用现有语义 |
| `status` | `provisional,insufficient` | 新增：数据状态多选；缺省为全部 |
| `view` | `timeline` / `list` | 新增：桌面默认 timeline，移动窄屏默认 list |
| `focus` | `event_03np9s5j` | 新增：当前选中或定位事件 |
| `compare` | `event_a,event_b` | 新增：最多 3 个事件 ID，顺序即用户选择顺序 |

规则：

- 空参数必须删除，不保留 `?status=` 这类噪声。
- 非法事件 ID 不写入对比栏，显示一次可恢复的提示。
- `focus` 不等于 `compare`；focus 表示当前定位，compare 表示用户明确加入对比。
- 地区筛选、时段、对比选择在进入事件页和返回时保留。

## 6. 页面结构

### 桌面端（>= 1100px）

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 产品名 / 当前数据版本                                      本地服务状态       │
├──────────────┬──────────────────────────────────────────────┬────────────────┤
│ 浏览范围      │ 面包屑 + 当前时段                            │ 上下文栏        │
│              │ 预制时段比例导航                              │                │
│ 地区          │ 统计摘要 + 图例                               │ 焦点事件摘要    │
│ 数据状态      │──────────────────────────────────────────────│ 或             │
│ 搜索          │ 共享时间刻度                                  │ 对比栏 2-3 项   │
│ 空地区开关    │                                              │                │
│              │ 地区行 A  ──◆──────██████────◆────             │ 共同地区        │
│              │ 地区行 B  ────────◆─────────██████──           │ 时间重叠        │
│              │ 地区行 C  · 本段未收录                         │ 状态差异        │
│              │                                              │                │
│              │ 共享时间刻度                                  │                │
└──────────────┴──────────────────────────────────────────────┴────────────────┘
```

### 平板端（780-1099px）

- 左侧筛选折叠为顶部工具行。
- 上下文栏默认收起；选择事件后从右侧滑出，宽度不超过 360px。
- 时间轴保持横排，但减少同时显示的标签数量，溢出进入聚合点。

### 移动端（< 780px）

```text
┌──────────────────────┐
│ 产品名 / 服务状态     │
├──────────────────────┤
│ 时段导航 / 筛选入口   │
│ 时间轴 | 年表         │
├──────────────────────┤
│ 概览与覆盖状态        │
├──────────────────────┤
│ 年表列表（默认）      │
│ 时间                 │
│ 标题                 │
│ 地区 / 状态 / 加入对比│
├──────────────────────┤
│ 底部对比栏（有选择时）│
└──────────────────────┘
```

移动端不把横向时间轴作为默认阅读方式。用户切换到时间轴时，只显示刻度和标记，标题通过点选后的底部详情呈现。

## 7. 核心组件

### 7.1 顶部栏

- 高度约 64px，保留产品名、当前数据版本和本地服务状态。
- 不再使用过多说明文字；覆盖限制由主视图中的覆盖组件表达。

### 7.2 筛选区

保留现有地区多选和搜索，新增：

- 数据状态多选：`provisional`、`insufficient`，未来兼容 `verified`、`disputed`。
- “显示无记录地区”开关：默认开启，空行压缩显示；关闭后只显示当前筛选下有事件的地区。
- 清除筛选：一次清除地区、状态和搜索，但不清除当前时段和对比选择。

### 7.3 预制时段导航

当前大尺寸时段卡改为紧凑比例导航：

- 子时段按时间跨度比例排列；空间不足时保留最小点击宽度并显示横向滚动提示。
- 每个子时段显示标题、样本数和覆盖状态。
- `checked_empty`、`unbuilt`、`failed` 用不同文本状态表达，不能只靠颜色。
- 不可展开时段不显示伪按钮。

### 7.4 时间矩阵

这是主页主画布：

- 顶部和底部各有一条共享刻度，当前时段起止明确标出。
- 点事件使用菱形或小圆点；区间事件使用横条，起止端点清楚。
- 同一地区行内允许最多 3 层标签；超出后聚合成“n 个事件”，点击展开当前位置的小列表。
- 标签优先显示事件短标题和年份；空间不足时先隐藏年份，再聚合标签，不低于 11px。
- hover、焦点和选中状态使用同一套高亮；键盘 Tab 可到达每个可见事件或聚合点。
- 同一事件跨地区出现时，聚焦其中一个 placement 会高亮其他 placement，并显示一条细的纵向参考线。

### 7.5 年表列表

列表不是主桌面视图，但它是移动端和无障碍的重要退路：

- 按时间排序，不按地区卡片网格排列。
- 每行显示时间、标题、地区、类型、数据状态和“加入对比”。
- 区间事件显示起止时间；世纪或约数日期显示“约”和精度。
- 筛选无结果时说明是筛选结果为空，不暗示历史为空。

### 7.6 上下文栏与对比栏

无焦点事件时，上下文栏显示当前范围覆盖摘要，不显示假推荐内容。

有焦点事件时显示：

- 标题、时间、地区、类型、数据状态。
- “打开详情”和“加入对比”。
- 若事件跨地区，列出所有已关联地区。

对比栏规则：

- 最多 3 个事件；达到上限时“加入对比”禁用并说明上限。
- 并排字段：时间、持续长度、地区、共同地区、类型、数据状态、时间重叠。
- 可移除单项、清空全部、打开单项详情。
- 对比栏只使用当前 API 已能返回的字段；不展示后端尚未提供的来源数。

### 7.7 事件详情页

保留现有功能，但调整首屏结构：

```text
返回时间线
标题
时间 / 地区 / 类型 / 数据状态 / 加入对比

主列：讲解、媒体、临时追问
侧栏：事实摘要、时间线位置、来源、相关事件
```

窄屏时侧栏移到主列之后。页面不新增营销式头图，不伪造图片。

## 8. 状态与文案

| 场景 | 显示原则 |
| --- | --- |
| 服务不可用 | 明确本地服务不可用，保留返回和重试，不显示空时间线 |
| 时段未构建 | 显示“未构建”，说明不是已查为空 |
| 已查为空 | 显示查询范围和“已按当前来源检查为空” |
| 筛选无结果 | 显示“当前筛选没有匹配事件”，提供清除筛选 |
| 地区无样本 | 地区行压缩显示“本段未收录”，不占正常事件高度 |
| 数据不足 | 事件旁显示“来源不足”，详情解释证据状态 |
| 对比上限 | 显示“最多同时比较 3 个事件” |
| 非法 URL | 忽略无效参数并提示已恢复可用状态 |

## 9. 视觉方向

整体保持“研究工具”气质：安静、密集但可扫读，不使用大 hero、营销卡或装饰性插图。

| 语义 | 建议 |
| --- | --- |
| 背景 | 低饱和暖灰或纸面灰，避免纯白长页 |
| 主色 | 深青绿，用于当前时段、焦点和主要操作 |
| 强调色 | 暗金，用于刻度和关键边界 |
| 警示色 | 赭红，用于来源不足、失败和非法状态 |
| 中性色 | 墨绿灰文本、浅灰分隔线 |
| 字体 | 标题可使用现有 serif；正文和控件使用系统 sans，不随视口缩放 |
| 圆角 | 控件和事件标记保持小圆角，避免大卡片感 |

颜色必须配合文字、图标或线型，不作为唯一状态编码。地区不使用 7 种高饱和颜色；地区身份靠行标题和筛选状态表达。

## 10. 数据与接口方案

### MVP 不新增后端接口

第一版可通过现有 `/api/timeline` 返回的 placements、event、region、period 完成：

- 时间矩阵、地区行、时段导航和数据状态筛选。
- 焦点事件和跨地区高亮。
- 2 至 3 个事件的基础对比。
- 年表列表。

### 后续可选接口

当对比栏需要来源数或跨时段定位时，再新增：

| 方法 | 路由 | 用途 |
| --- | --- | --- |
| GET | `/api/compare?ids=...` | 一次返回 2-3 个事件、placements、evidence_count |
| GET | `/api/coverage` | 返回批次覆盖摘要，供覆盖栏使用 |

这两个接口不是本设计 MVP 的前置条件。

## 11. 技术影响

预计实现时主要影响：

- `src/web/App.tsx`：拆出筛选、时段导航、时间矩阵、年表列表、对比栏和详情页区块。
- `src/web/styles.css`：重建主页布局与响应式规则，移除旧事件卡片网格。
- 新增 `src/web/timeline-view-model.ts`：把 placements 转为刻度、行、标记、聚合和对比 ViewModel。
- 新增 `src/web/timeline-layout.ts`：负责标签分层、聚合阈值和区间截断，便于单测。
- `tests/e2e/timeline.spec.ts`：更新选择器和新交互验收。

不需要改 `data/timeline/*.jsonl`。不需要改 Fastify API 即可完成 MVP。

## 12. 测试与验证阶梯

1. 单元测试：BCE/CE 排序、区间截断、标签聚合、跨地区同事件归组、URL 状态解析。
2. API 回归：现有 timeline、period、event、search 接口行为不变。
3. 浏览器测试：1440×900、1024×768、390×844；无水平溢出，标签和控件不重叠。
4. 交互测试：筛选、搜索、下钻、返回、焦点高亮、加入/移除对比、刷新恢复。
5. 空态测试：未构建、已查为空、筛选无结果、服务离线、非法 URL。
6. 可访问性检查：键盘可达、焦点可见、状态不只靠颜色、触控目标足够。
7. 文档验收：README、Todo、证据等级同步，不把设计文档写成实施完成。

## 14. 风险与待确认项

- 当前只有 16 个事件，无法证明全球高密度下仍清晰；实现时需补一个 synthetic fixture 验证聚合。
- 当前根时段跨度和子时段宽度差异较大；时段比例导航可能出现极窄段，需最小宽度和横向滚动策略。
- 右侧上下文栏在 1100px 附近可能压缩主画布；实现时需在 1024 宽度验证折叠规则。
- 事件标题长度差异较大；标签策略必须优先保证中文可读，不用无限缩小字号。
- 对比栏 MVP 不显示来源数；若用户需要证据强弱对比，再新增 `/api/compare`。
- 本设计未改变 P5 全球数据缺口，也不替代 P6-3 页面完整验收。
